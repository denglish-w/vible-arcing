# Contract: Account APIs and personal data

Paths below are the proposed application facade. Better Auth is mounted at `/api/auth/[...all]`; every enabled library route must pass the same policy, including the independent inbox-recovery session handoff. Disable or wrap library endpoints that could bypass consent, confirmation, recent authentication, explicit linking or the mail acceptance boundary.

## Request boundary and common results

Apply configured Host and HTTPS policy before database access. Mutations require same-origin checks and CSRF protection; OAuth callbacks use library state/nonce/PKCE and exact registered callback URI, including Apple's cross-site form POST. No wildcard trusted origins. Server actions retain their framework Origin check and the application checks. Public corpus remains public; personal responses use `Cache-Control: private, no-store` and are not put in shared Next caches.

Resolve actor from the current database session and require confirmed email for all work lists, creates, saves, imports and exports. Direct personal-record requests return the identical 404 page/body/headers for absent, foreign or signed-out ids, with a generic sign-in offer; never redirect based on whether a record exists. A signed-out create/list intent may return `signin-required` because it names no record. Unconfirmed setup returns `confirmation-required` without exposing work. A stale loaded session marker returns `account-changed` only after proving that it refers to the request's own client session, with no foreign record details.

App mutations return `{ ok: true, ... }` or `{ ok: false, reason, ... }`. Reasons include `invalid`, `not-found`, `signin-required`, `confirmation-required`, `reauth-required`, `account-changed`, `conflict`, `rate-limited` (with retry seconds), `email-unavailable`, `provider-unavailable` and existing kind-specific save refusals. HTTP facade uses 400 invalid, 404 concealed record, 409 conflict/account change, 429 throttled and 503 unavailable; auth forms map expected states to accessible UI. Do not reveal database exception details or addresses in logs.

## Authentication and account operations

| Interface                                     | Input and behavior                                                                                                                                                                                                                                                                                      |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/account/signup`                    | Email/password, accepted consent version and optional first-account browser settings. Generic accepted response for new/duplicate email; existing-address email explains signin/reset. Pending registration only until proof. Known delivery failure returns generic retry without address enumeration. |
| `POST /api/account/confirm/resend`            | Email; generic accepted result, independent rate limit; replace or expire old confirmation token safely.                                                                                                                                                                                                |
| `GET /confirm?token=…` then confirmation POST | GET displays landing only; POST consumes single-use proof and completes account creation/legacy claim when eligible. Remove token from browser address/history; no third-party content on token pages; Referrer-Policy no-referrer. Works in another browser without assuming its current account.      |
| `POST /api/account/signin`                    | Email/password, explicit `keepSignedIn=false` default, sanitized return path. Rotate cookie on success. Unknown user/wrong password have equivalent error and throttle behavior.                                                                                                                        |
| `GET /api/account/session`                    | Minimal current identity, confirmation state, settings and opaque client-generation marker; no secrets. No-store.                                                                                                                                                                                       |
| `POST /api/account/signout`                   | Revoke current session, expire cookie; broadcast identity change, restore anonymous settings, clear account views.                                                                                                                                                                                      |
| `POST /api/account/signout-all`               | Revoke all sessions atomically; all clients stop on next action.                                                                                                                                                                                                                                        |
| `POST /api/account/password/reset-request`    | Password enabled only: generic response and one-hour reset link for an existing confirmed address. If password is disabled, offer the separate built-in recovery request; never issue an unusable password reset.                                                                                       |
| `POST /api/account/password/reset`            | Password enabled only: purpose-bound token plus validated password. Atomic consume/change/revoke; redirect to enabled password signin or rotate initiating session. When password is disabled, offer the separate inbox-recovery flow instead of creating an unusable password.                         |
| `POST /api/account/reauth`                    | Password or callback intent for an already linked enabled provider; prove the same account and rotate session. A different provider user cannot satisfy reauth.                                                                                                                                         |
| `POST /api/account/password/change`           | Fresh auth and new password; common-password rules, notification and revoke other sessions.                                                                                                                                                                                                             |
| `POST /api/account/email/change`              | Fresh auth and new address; send new-address proof, keep old until confirmed. Final POST rechecks uniqueness, invalidates other sessions, notifies old address. Never a client-supplied account target.                                                                                                 |
| Provider signin                               | `/api/auth/sign-in/social` with provider and app-only callback path. Single-use transaction binds consent and signin intent; validate returned identity. Same-email confirmed account is a conflict requiring existing-account signin and explicit linking.                                             |
| Provider/password link or unlink              | Explicit account-settings operation after fresh auth and address proof. Refuse already-linked provider and last enabled usable method. No implicit-link option exposed to clients.                                                                                                                      |

Return paths must be parsed against the configured origin and reduced to a local relative path. Reject protocol-relative, backslash, credential-bearing, malformed and external paths; fall back to `/`. Do not place saved text or arbitrary return paths in OAuth claims/scopes. Provider profile scopes are identity only.

Cookies are HttpOnly, SameSite=Lax and path `/`; Secure in HTTPS/live, host-only, with `__Host-` prefix where applicable. Local HTTP uses the narrowly scoped development cookie. Apple's form-post callback needs the library's documented transient callback mechanism; do not weaken the main session cookie to make it work. Verify callback behavior in real browsers.

Ordinary cookies omit persistent expiry; restored browser sessions may retain them until the 12-hour server idle limit. Explicit signout and revocation always invalidate the database session.

`POST /api/account/recovery/request` is always available for an existing active account with confirmed email, independently of AUTH_METHODS, with the same generic response and independent email throttle as reset. `GET /recover-account?token=…` renders a landing form; `POST /api/account/recovery/complete` consumes the purpose/account/current-email/epoch-bound proof, revokes old sessions and creates a five-minute one-use issuance receipt atomically. The response completes same-browser auth-session issuance through the library after commit; bind the issuance receipt to the landing browser’s HttpOnly nonce and post-revocation account epoch; settle it atomically to one session id and return the same session on a lost-response retry within five minutes, never replay the email token. No prior session or new password is required, no account is created/linked and normal owner guards apply afterward. The resulting session is nonpersistent with fresh-auth time set to recovery completion. A fresh recovery can replace an expired/failed handoff. Recovery remains available when every method linked to that account is operator-disabled; configuration must still enable at least one ordinary method for general signup.

## Work and settings

Existing work actions, `/work`, analysis/diagram detail pages and `GET /api/analyses/[id]/export` keep their document/revision/export shapes while adding mandatory actor checks. Every read, count and conflict lookup includes `(owner_id, id)`; conditional writes additionally include expected revision. The server derives owner on create. No accepted payload has an authoritative owner field. Rejected foreign writes leave all rows unchanged and return no revision or validation detail.

Apply the same checks to learning attempt/history/export and translation documents, selection preferences, names, recency and receipts when those features exist. Public parsing checks may remain read-only; no personal summary is embedded for a signed-out reader. Account changes stop queued old-owner writes even if record creation had not yet returned an id.

`GET/PATCH /api/account/settings` returns or revision-checks validated display settings for the current actor. Missing/unreadable/later fields default independently; anonymous setting edits never reach the account endpoint. On sign-in apply account settings without reload; on signout restore the browser's anonymous snapshot.

## Account portability and deletion

`GET /api/account/export`: confirmed actor, same-origin download checks, one streaming `application/x-ndjson` attachment with nosniff/no-store. Header/record/trailer and omission rules are in [the model](../data-model.md). Snapshot includes only that actor's records/settings, including legacy records needing attention.

`POST /api/account/import/upload`: authenticated operation UUID, chunk offset/digest and at most 8 MiB of bytes from the single export file. Stage privately, bind to actor/generation, accept identical retries and reject changed offsets/payloads. Sequential chunks have no aggregate byte or record-count cap; low disk pauses resumably.

`POST /api/account/import/preview`: stream the completed staged file, validate header/version/trailer counts/digest, store paged indexed per-record validation results and explicit settings choice; no work writes. Return operation id, counts, preview digest and first report cursor. `GET /api/account/import/report?operation=…&cursor=…` exposes at most 100 entries to its actor; the full report downloads as a stream.

`POST /api/account/import`: operation UUID, sealed preview digest, settings choice and current actor/generation; process at most 1,000 records per call with record receipts and revalidation. Return `{ operationId, importedCount, rejectedCount, nextCursor, settingsResult }`, not unbounded arrays. Result entries (`index`, `kind`, `newId` or `reason`) live in the paged report. Per-record failures do not undo other valid records; infrastructure failures preserve resumable receipts. The same operation never duplicates successful entries; a new operation creates new copies. Reject malformed/new-version framing before work writes; enforce record limits from each shared save validator, never a whole-export 50 MiB/10,000-record cap. Settings apply once after the final batch. Delete abandoned stages/reports after seven days and cascade them on account deletion.

`GET /api/account/deletion-preview`: current counts by kind plus total and export offer. `POST /api/account/delete`: fresh auth, typed canonical account email, preview revision/fingerprint and operation UUID. Recompute counts; if work changed, show revised confirmation rather than silently deleting a changed set. Inside one transaction, recheck actor/freshness/typed email/preview fingerprint, delete account/method/session/settings/work/auxiliary rows and enqueue a minimal account-independent completion notice. No send occurs before commit. A failed check or rollback leaves no notice eligible for delivery. Clear browser state after commit; expose notice pending/sent/failed separately through a short-lived opaque receipt and retry delivery for seven days without restoring the account. Provider revocation status is also separate from local deletion completion. No record, token or same-email signup can resurrect the old account. Account ids are never reused.

## Required adversarial contract tests

Additionally test signed-out recovery with password disabled and only a disabled linked provider; both restored/non-restored browser sessions; single-file round trips exceeding 10,000 records and 50 MiB; paged reports/chunk retry/disk exhaustion; notification rejection after commit; and a concurrent deletion-preview change that produces no completion notice.

Compare absent/foreign/signed-out direct requests for every personal endpoint; test invalid content against foreign ids, stale revisions, list/count/search and export. Test callbacks with wrong issuer/audience, missing nonce/state, replay, unverified/missing Microsoft email, conflicting verified email, replaced provisional signup and provider already linked elsewhere. Test method disabling, direct library endpoints, cross-origin requests, unsafe return URLs, rotated session use, two concurrent claims, mail failure and account deletion during an in-flight save.
