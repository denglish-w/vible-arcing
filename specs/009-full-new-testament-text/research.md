# Research: Full New Testament Text

All findings were measured on 2026-11-16 against the pinned MACULA Greek commit `8423afe47b9e8f24b7772e808af45c7159a6fe7e`, with the 27 `SBLGNT/lowfat` files downloaded outside the repo and the current extractor's functions run over every chapter.

## R1. Does the existing extractor handle every book?

- **Decision**: Reuse `parse_book`, `following`, `word_record` and `chapter_words` unchanged; generalise only the command around them.
- **Rationale**: Run over all 27 files they produced 260 chapters and 137,741 words with zero errors: no missing ids, lemmas or parts of speech, no duplicate references or ids, no markup characters. Every book's chapters run contiguously from 1 to the count in `src/lib/books.ts`. Philippians 1 and `attribution.json` regenerated byte-identical to the committed files.
- **Alternatives considered**: A new ingest script. Rejected: the spec requires extending the existing one, and nothing in it needs rewriting.

Observed data: 830 words have no gloss (shown without one, as today). Parts of speech: noun, verb, det, conj, pron, prep, adj, adv, ptcl, num, intj. Following punctuation: space, comma, full stop, ano teleia, Greek question mark and elision marks (’ and a rare ᾿).

## R2. Script shape and name

- **Decision**: `git mv scripts/ingest/sample_chapter.py scripts/ingest/ingest.py`, and change its command to take a directory holding the 27 book files, the commit and the output directory, always producing the whole New Testament. Drop the single-chapter mode.
- **Rationale**: "sample_chapter" would misdescribe the script; `git mv` keeps its history, which satisfies "extended, not replaced". One mode means the committed corpus can never be a partial set.
- **Alternatives considered**: Keep the name and add `--all` (misleading name, two modes to test); a `--book` filter (no current need).

## R3. All-or-nothing output (spec FR-010)

- **Decision**: Read and check all 27 books in memory first, write every file into a fresh sibling directory (`<out>.new`), then swap it into place by rename and delete the old directory. Any error before the swap leaves the output directory untouched and removes the temporary one.
- **Rationale**: Mirrors the seed's temp-file-and-rename pattern. Replacing the whole directory also removes stale chapter files from a previous run.
- **Checks added at book level**: exactly the 27 expected files present; each root is a lowfat `book` with a unique code; every word's `ref` names that book; chapters contiguous from 1; word ids unique across the whole New Testament.

## R4. Getting the source

- **Decision**: New `scripts/ingest/fetch.sh <dir>` downloads the 27 files from `raw.githubusercontent.com/Clear-Bible/macula-greek/<pinned commit>/SBLGNT/lowfat/` with `curl -sSfL` into a directory the caller names, outside the repo. The pinned commit is defined in this script and documented in the README; the ingest still receives it as `--commit` and writes it into every chapter file.
- **Rationale**: A URL at a commit SHA does not change, and the byte-identical regeneration check (SC-006) detects any difference. Downloading stays separate from parsing, so the parser only reads local files (downloaded data is treated as untrusted).
- **Alternatives considered**: Download from Python with `urllib` (mixes network with parsing); a sha256 manifest of the source files (redundant given the fixed URL plus output comparison); committing the 109 MB of XML (unnecessary bulk).

## R5. Committed output size and format

- **Decision**: Keep pretty-printed JSON exactly as today (`indent=2`, `ensure_ascii=False`), committed under `corpus/v1/`.
- **Rationale**: 36 MB on disk but about 3 MB compressed, which is roughly what git stores; diffs stay reviewable if MACULA is ever bumped. Compact JSON (23 MB) would change Philippians 1's bytes for little gain, since the app reads the store, not the files.
- **Alternatives considered**: Compact JSON; one file per book; Git LFS; generating at build time from downloaded XML (builds would need the network).

## R6. Seed, store and reader at full size

- **Decision**: No code change to `src/db/seed.ts`, `src/db/corpus.ts`, the reader pages or the Docker entrypoint.
- **Rationale**: Seeding all 260 files took 3.6 s and produced a 22 MB store. `ingestHash` changes with the files, so `scripts/seed-if-stale.ts` rebuilds existing Philippians-only stores automatically. `getChapter` read Matthew 26 (1,240 words) in 6.4 ms and Luke 1 in 3.4 ms; `listBooks` took 0.4 ms. The strict zod parser already rejects any field outside the whitelist, a second guard for FR-005.
- **To verify in the browser** (quickstart): render time of Matthew 26 with part-of-speech colouring on, since the reader renders one interactive element per word.

## R7. Tests at full size

- **Decision**: In `src/db/seed.test.ts`, the behaviour tests (atomic swap, refusal, determinism, ordering, WAL cleanup) seed a small fixture copied from `corpus/v1/attribution.json` and `corpus/v1/PHP/1.json` instead of the whole committed corpus. A separate `describe("committed corpus")` block seeds the full committed corpus once and asserts 260 chapters and 137,741 words, every chapter in `BOOKS` present, one MACULA commit, and Philippians 1 still 501 words with its first and last ids unchanged.
- **Rationale**: Copying and seeding 36 MB in every `beforeEach` would add seconds per test, and the behaviour under test does not depend on corpus size. One full seed covers SC-001, SC-002 and SC-005 in CI.
- **QA script**: `scripts/qa/reader.cjs` opens Matthew 28 to see the unavailable state. It will instead check that Matthew 28 shows text and still follows the next link to Mark 1. The unavailable state stays covered by its Storybook story.

## R8. Unavailable-state copy

- **Decision**: `ChapterUnavailable` stops saying Philippians 1 is the readable chapter and stops linking there. It now says this chapter is missing from the installed Greek text, which is out of date, and to run `npm run db:seed`. `ChapterNotInstalled` (no store at all) is unchanged.
- **Rationale**: With the full corpus the state only appears when the store is older than the code (spec FR-012). The Storybook story and its axe check stay.

## R9. Docker image and CI

- **Decision**: No Dockerfile change. `COPY corpus/v1` now copies 36 MB, and the first container start seeds for a few seconds.
- **Rationale**: CI's smoke test (credits notice, foreign Host gets 403) keeps working; the image grows by about 36 MB uncompressed, acceptable for a local app. A local arm64 build does not prove the amd64 CI build, so CI is the check.
